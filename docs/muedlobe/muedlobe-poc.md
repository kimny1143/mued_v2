# MUEDlobe PoC Validation Log

MUEDlobeが多様な認知プロファイルを正しく測定・分類できるかを検証する。
各ケースは「このパターンの人がMUEDlobeを使うとどう測定されるか」の事例記録。

---

## Case 1: 高WM・低PS型（Architect傾向）

WAIS既受検者による検証。MUEDlobeが変数間の凹凸を正しく捉えられるかがポイント。

### 参照データ（WAIS-III、約10年前）

| 指標 | スコア | ランク |
|------|--------|--------|
| WM (作動記憶) | **128** | Superior |
| PO (知覚統合) | **116** | High Average |
| VC (言語理解) | **104** | Average |
| PS (処理速度) | **97** | Average |

**特徴:** WM-PS間に31ptの有意差。典型的な「構造把握は強いが処理速度は平均域」パターン。

### 期待されるMUEDlobe検出パターン

- `high_wm_low_ps` — WM-PS差が閾値超え
- `high_wm_low_vc` — WM-VC差が閾値超え
- `high_pr_low_ps` — PR-PS差が閾値超え
- **Architect type** — 高WM, 低PS, 高PR の複合

### 2026-02-07: PS-1 Symbol Match

| 項目 | 結果 |
|------|------|
| 正答 | **45** |
| 誤答 | **0** |
| 総試行 | 45 / 120秒 |

**所見:**
- ミスゼロ、120秒で45問。WAIS Symbol Searchの平均raw score（約30）を大幅に上回る
- WAIS-III PS 97（平均域）の人がこのスコアを出すのは、ゲーム側の弁別力不足を示唆

- 紛らわしいペア（◇と◆、○と◎など）の出現頻度を意図的に上げるべき
- 現状のスコアでは PS 97 と PS 130 の人の差がつかない可能性が高い

**検証ステータス:**
- [ ] PS平均域がスコアに反映されるか → **未達成**。天井効果で弁別できていない

### 2026-02-07: WM-2 Mental Math

| 項目 | 結果 |
|------|------|
| Correct | **14** / 15 |
| Total Score | **19.98** |
| 不正解 | Level 2, Q5（2桁加減算） |

**所見:**
- 14/15正解。天井効果が顕著 — 問題が簡単すぎて弁別力が低い
- 現状の問題セットはWAIS Arithmeticの前半（Item 1-10相当）のみ
- WAIS後半の高難度問題（多段推論、小数/割合の暗算、条件付き文章題）が未実装
- 被験者のWAIS-III算数下位検査は18（天井付近）なので、MUEDlobeでも天井に張り付くのは整合的
- ただし、他のWMプロファイルの人（WM平均域など）でも高得点が出る可能性が高く、測定としては不十分

**要改善:**
- Level 6-8 の追加が必要（WAIS Item 14-20相当の難易度）
  - 例: 「8台で6日の仕事を半日で終わらせるには？」（比例推論）
  - 例: 「3個2,750円を10,000円で買ったらおつりは？」（複合計算）
  - 例: 「AはBの3倍、BはCより5大きい、Cが4のときAは？」（多段変数追跡）
- 現状のLevel 1-3は練習問題扱いにして、Level 4以降で本測定とすべき
- 不正解1問がLevel 2（易）なのは注意散漫か聴き取りミスの可能性。音声品質も要検証

### 2026-02-07: PS-2 Code Fill

| 項目 | 結果 |
|------|------|
| 正答 | **96** |
| 誤答 | **0** |
| Raw Score | **96** |

**所見:**
- 120秒で96問、ミスゼロ。完全な天井効果
- 被験者フィードバック: 「途中で場所を覚えたから、その場所を押せばいいだけになった」
- **設計上の致命的欠陥**: ボタン配置が固定のため、digit→symbol変換ではなく**位置記憶**で回答できてしまう。これはPSではなくWMの空間記憶を測定している
- WAIS Codingは紙と鉛筆で「書く」ため位置記憶ハックが効かない

**要改善（優先度: 高）:**
- ボタン配置を毎回ランダムシャッフルする → 位置記憶を無効化
- または、記号を表示して対応する数字を入力する逆方向タスクに変更

### 2026-02-07: ATT-1 Focus Flow

| 項目 | 結果 |
|------|------|
| Hit Rate | **0.99** (36/36 targets) |
| False Alarm Rate | **0.02** (3/144 non-targets) |
| d' | **4.36** |
| RT CV | **0.17** |
| Mean RT | **555ms** |
| Raw Score | **3.62** |

**所見:**
- d' 4.36は非常に高い（一般的にd'>3.0で優秀）
- RT CV 0.17は安定（CV<0.2で安定の指標）
- misses=0 は完璧なhit rateだが、3件のfalse alarmがある → 反応抑制は完璧ではない
- WAIS-IIIにATT対応指標がないため外部基準との比較は不可

**UXフィードバック:**
- 被験者: 「クリックできてたかわかりづらい」→ **クリック時のフィードバック（音/視覚）が必要**
- 現状はクリックしても何も起きないため、押した確信が持てない
- 短い音（ピッ）またはボーダーのフラッシュを追加すべき

**要改善:**
- クリック時の即時フィードバック（音または視覚エフェクト）を追加（優先度: 高）
- ターゲット判定とは独立にフィードバックする（正解/不正解は見せない、押した事実だけ通知）

### Phase 2 総括

**機能しているゲーム:**
- **Tone Sequence** — 適応型メカニズムが弁別力を担保。音楽モダリティ有利の補正は要検討
- **Word Bridge** — 抽象度スコアの設計が天井効果を防いでいる。最も測定として健全
- **Focus Flow** — CPTとして基本動作OK。UXフィードバック改善が必要

**要チューニング（難易度不足）:**
- **Mental Math** — Level 6-8追加（多段推論、比例、複合計算）
- **Pattern Complete** — hard問題の本格化、または適応型への変更
- **Symbol Match** — 記号の類似度向上、SVG化

**設計要修正:**
- **Code Fill** — ボタン配置ランダム化（位置記憶ハック対策）。最優先
