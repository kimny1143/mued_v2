## 2. ⑤ は自動——★ただし ④ に依存している（★切り離さない）

**⑤ は3層とも実在する**（mued 実測。★**「定数が在る」→「書かれる」→「消費時に効く」を別々に測っている**＝**定義されている ≠ 強制されている**ため）:

1. **定数** `lib/dial/pricing.ts:108` — `CANCEL_GRACE_DAYS = 30`
2. **書き込み** `webhooks/stripe/route.ts:1352-1359` — `customer.subscription.deleted` で残高 >0 の grant に `expiresAt = now + 30日` を UPDATE
3. **消費時に効く** `credits/consume/route.ts:82` と `credits/balance/route.ts:41` の**両方**が `or(isNull(expiresAt), gt(expiresAt, now))` で絞る

### ★★30日の起点は「Stripe が `deleted` を飛ばした瞬間」

| ④ の操作 | 何が起きるか |
|---|---|
| ★**「請求期間の終了時にキャンセル」**（正） | **期間終了時に `deleted`** → **そこから30日** ＝ **④も⑤も開示どおり** |
| ★**「即時キャンセル」**（誤） | ★**その場で `deleted`** → **残りのサービス期間を失う**（④違反）**と同時に、30日の時計も早く回り始める**（⑤も短くなる） |

★**∴ ④を破ると、開示が2箇所 同時に偽になる。** ★**しかも利用者からは「30日あるはずが短い」としか見えず、原因が④だと辿れない。**

★**この文書で ④ と ⑤ を別項目に分けているが、★連鎖は切れていない。** **④を操作する時は、⑤の起点を決めている自覚を持つこと。**

## 3. 解約が来たときの手順（★これだけ覚えれば足りる）

1. `support@mued.jp` に件名「**Hoo Pass解約**」が届く（★**②＝この受信箱を見ている人が居ることが前提**）
   - ★**気づきは kimny の iPhone Gmail プッシュ／一次は conductor**（checkin / checkout / patrol + 自ターン頭で検索）
   - ★★**検索は最低2本 打つ**——**`to:support@mued.jp newer_than:7d`** ＋ **相手・話題での検索**。
     ★**`to:` だけでは足りない**（**2026-07-30 に FastSpring の返信2通を 31時間 見落とし、kimny が外部検出**）
   - ★**返信は元スレッドに付くとは限らない**（**実例: 元スレッドの最終受信は 7/17 で正しく、返信は別スレッドに付いていた**）
2. ★**営業日24時間以内に**（③）Stripe で当該サブスクリプションを解約する
3. ★★**その時「請求期間の終了時にキャンセル」を選ぶ。「即時キャンセル」を選ばない**（④＝**⑤の起点でもある**・§2）。★**「即時キャンセル」を選ぶと、特商法の開示がその時点で偽になる**
4. **残クレジットの30日は自動**（⑤）。**日割り返金はしない**（⑥）
5. **完了を依頼者へ返信する**（★開示には無いが、②③を守った証跡が残らないため）
