# MUED.jp サイト改善指示書 for Claude Code

## このドキュメントの目的

AIが「指示を実行する」だけでなく、「決断・批判・削除」を行いながらサイトを改善するための指針。

---

## 第1章：AIへの行動原則

### 必ず守ること

1. **作る前に疑え**
   - 「この要素、本当に要る？」を全要素に問え
   - 答えが曖昧なら、まず無しで作れ

2. **主役を1つ決めろ**
   - 各セクションで「一番見せたいもの」を1つだけ決めろ
   - 決まるまでコードを書くな

3. **70点を並べるな**
   - 全要素が同じ存在感 = 失敗
   - 1つを120点、残りを60点にしろ

4. **「できます」より「やめましょう」**
   - 追加より削除を提案しろ
   - 迷ったら削れ

5. **批判してから作れ**
   - 現状の問題点を3つ以上挙げてから改善案を出せ
   - 「いい感じですね」は禁止

## 第2章：MUEDサイトの設計意図

### ブランド

- **MUED** = ミューズの教え、神秘ではなく方法論
- **Hoo** = フクロウのキャラクター、ユーザーのガイド役
- **トーン** = プロフェッショナルだが親しみやすい、夜のスタジオ感

### ユーザー導線の優先順位

```
1. Hooを認知させる（キャラクターを覚えてもらう）
      ↓
2. MUEDnoteに誘導（メインアプリ、サブスクモデル）
      ↓
3. MUEDearを見せる（サブアプリ、広告モデル実験）
      ↓
4. サインアップ（アプリDL後でよい、急がない）
```

### 絶対にやらないこと

- サインアップを最優先にしない
- 2つのアプリを完全同格に見せない（視覚的順序はつける）
- Hooを脇役にしない

## 第3章：現状の問題点（これを修正せよ）

### 問題1：主役の不在

- 背景画像、Hoo、タイトル、ボタンが全て同じ声量で喋っている
- 視線の誘導がない

**修正方針**：Hooを主役にする。他は脇役。

### 問題2：背景画像が邪魔

- 暖色のスタジオ写真の上に白線のHoo → 埋もれる
- 「Geminiに作らせた」感が出ている
- 世界観を作るどころか、ノイズになっている

**修正方針**：背景画像を削除。ソリッドカラーまたは緩いグラデーションに。

### 問題3：ボタンの同格問題

- 紫と黄色のボタンが同じサイズ、同じ存在感
- 「どっちを押せばいい？」が分からない
- 色の理由が不明

**修正方針**：MUEDnoteを塗りボタン（主）、MUEDearをテキストリンクまたは小さめ線ボタン（従）に。

### 問題4：Hooが光っていない

- サイズが中途半端（主役なのに画面の1/4程度）
- 背景と色がケンカしている
- 静的で存在感がない

**修正方針**：Hooを1.5倍サイズに。後ろに薄いグロー。可能ならアニメーション（目が動く等）。

## 第4章：改善後のヒーローセクション設計

### レイアウト構成

```
┌─────────────────────────────────────┐
│            [日本語 | English]       │  ← 右上、控えめ
│                                     │
│               MUED                  │  ← タイトル、大きめだがHooより控えめ
│    ミューズの教え——神秘ではなく、方法論。│
│                                     │
│                                     │
│              ┌───┐                  │
│              │🦉│  ← Hoo: 大きく、グロー付き
│              └───┘      ここが視線の中心
│                                     │
│        「Hooがご案内します」          │
│                                     │
│      ┌──────────────────┐           │
│      │  MUEDnoteを見る  │           │  ← 塗りボタン、メイン
│      └──────────────────┘           │
│         MUEDearを見る →             │  ← テキストリンク、サブ
│                                     │
└─────────────────────────────────────┘
```

### 背景

- **推奨**：ダークグレー (#0a0a0a ~ #1a1a1a) のソリッド
- **代替**：上から下へ微かに明るくなるグラデーション
- **装飾**（任意）：画面下部に波形やキーボードをうっすら20%程度の不透明度で

### カラーパレット

```
背景：#0f0f0f（ほぼ黒）
テキスト主：#ffffff
テキスト従：#888888
アクセント主：Hooのテーマカラー（要定義、現状白なら白を活かす）
ボタン塗り：#6366f1（indigo系）または Hooに合わせた色
ボタン線：上記より薄く
```

### Hooの演出

1. **サイズ**：現状の1.5〜2倍
2. **グロー**：box-shadow または filter: drop-shadow で薄く光らせる
3. **アニメーション**（推奨）：
   - 目がゆっくり瞬きする
   - または hover で耳が動く
   - 過剰にしない、2-3秒に1回程度

## 第5章：実装時のチェックリスト

### 作業開始前

- [ ] 「このセクションの主役は何か」を言語化したか
- [ ] 「削除できる要素はないか」を検討したか
- [ ] 「なぜこの色か」を説明できるか

### 作業中

- [ ] 全要素が同じ存在感になっていないか
- [ ] 視線の流れは意図通りか（上→Hoo→ボタン）
- [ ] 背景がコンテンツの邪魔をしていないか

### 作業完了前

- [ ] スマホで見て3秒以内に「何をすればいいか」分かるか
- [ ] 「AI生成感」の原因（均一な余白、安全な色、決断の不在）がないか
- [ ] 「ここは削れたのでは」と思う要素がないか

## 第6章：Claude Codeへの追加指示

このプロジェクトでコードを書く際、以下を必ず実行せよ：

1. **コードを書く前に現状の批判を述べよ**
   - 「現状の問題点は〜」から始めろ

2. **変更案を出す時は「削除」を先に検討せよ**
   - 追加より削除が優先

3. **迷ったら確認せよ**
   - 「AとBどちらにしますか」ではなく「Aを推奨します、理由は〜。Bの場合は〜」

4. **「いい感じですね」「素敵です」禁止**
   - 完成後も「改善の余地があるとすれば〜」を添えよ

5. **決断を求められたら決断せよ**
   - 「お好みで」「どちらでも」は使うな
   - 根拠を添えて一つを推奨しろ

## 付録：参考にすべきデザインの特徴

Genspark等、「AI製だがプロっぽく見える」サイトの特徴：

1. **視線誘導が明確** - 見るべき順番が1秒で分かる
2. **階層がある** - 全部同格ではなく、主従がある
3. **色と機能が紐づいている** - 意味のない装飾色がない
4. **削られている** - 「入れられたけど入れてない」要素がある
5. **グリッドが見える** - 余白が計算されている
