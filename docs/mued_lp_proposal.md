# MUEDnote ランディングページ改修提案

## 背景・課題

現在のページは「判断を資産にする」という機能訴求が中心になっている。しかし、ユーザーリサーチの結果、「ログを取りたい」というニーズに対しては「いいね」「面白い」という反応はあっても「使いたい」には至らなかった。

本当のニーズは「使いたい」ではなく「知らん間にやっといてほしい」。

また、マスコットキャラクター「Hoo」が現在のページには一切登場していないが、これが本来の商品の核になるべき要素。

---

## 方向性の転換

### Before（現状）

- 訴求：「判断を資産にする」ツール
- 主役：機能（タイマー、文字起こし、ログ）
- トーン：生真面目なプロダクティビティツール

### After（改修後）

- 訴求：制作に寄り添うコンパニオン
- 主役：Hoo（glasswerksのマスコット）
- トーン：親しみやすい、愛着が湧く

---

## 体験設計の意図

ユーザーの体験の変遷：

1. 「タイマーか、キャラかわいいな」（入口）
2. 「休憩促してくれて助かる」（習慣化）
3. 「あれ、この子なんか俺のパターン知ってる...？」（気づき）
4. 「もうこの子なしで制作したくない」（愛着）

→ 気づいたらログが溜まっていて、Hooが自分の制作を一番知ってる存在になっている。

---

## 具体的な変更点

### 1. ファーストビュー

**現状：**

```
MUEDnote
Making music visible.
「なんでこうしたんだっけ」が消える前に。
作ってる最中の"判断"を、資産にする。
```

**変更後：**

- Hooのビジュアルを大きく配置
- 「ほほう（Ho-Hoo）」という鳴き声/吹き出し
- コピー例：「制作のそばに、いつもHoo。」または「休憩の時間、教えるね。」
- サブコピーで軽く機能に触れる程度

### 2. 機能説明セクション

**現状：** 機能を3カラムで並列に説明

**変更後：**

- Hooが主語になる説明に変更
- 「Hooが休憩を教えてくれる」
- 「Hooに話しかけると、覚えててくれる」
- 「Hooはあなたの制作パターンを知っていく」
- ログ機能は「裏側でこんなことも」程度の扱い

### 3. トーン&マナー

- 「資産」「蓄積」「判断ログ」→ 硬い言葉を減らす
- Hooの一人称や語りかけを入れる
- 親しみやすさ、ゆるさを出す

### 4. CTA

**現状：** 「記録を始める」「リリースを待つ」

**変更後：** 「Hooと始める」「Hooに会う」など、キャラクター起点の表現

---

## 優先度

1. ファーストビューにHooを配置（最優先）
2. コピーの書き換え（Hoo主語に）
3. 機能説明の構成変更
4. 全体のトーン調整
