# MUEDnote ロードマップ

**策定日**: 2026-02-25
**ステータス**: Phase 0 確定・実装待ち
**前提ドキュメント**: [サブスク戦略](./subscription-strategy-2026-02.md)

---

## 全体像

```
Phase 0 → Phase 1 → Phase 2 → Phase 3
準備       Hoo が喋る   ログが貯まる   Hoo が覚醒する
           (Basic MVP)  (Basic 完成)   (Premium)
```

- Phase 1 リリース時点で Basic 課金開始
- Phase 2 は Basic のアップデートとして順次追加
- Phase 3 は Phase 2 のデータ蓄積状況を見てから判断

## Phase 0: App Review 準備

**目的**: Basic リリースの前提条件を整え、最小変更で App Review を通過する

### 背景: 前回の App Review 経験

v1.0 の審査では以下が連鎖的に指摘された:
- ログイン強制 → ローカルで動く機能があるのに不要と判断された
- iPad 対応不足
- Sign in with Apple 未対応
- その他複数の指摘

最終的にログイン機能ごと外して通過したのが現在の v1.0。

### 今回の戦略

**最小変更で審査を通す → 通過後に順次機能追加**

- Free の全機能はログインなしで動く状態を維持（現状のまま）
- Basic 機能（Hoo 会話）タップ時にサインインを促す形にする
- **まず Hoo 会話だけを追加して審査に出す**（一気に入れない）

### タスク

| タスク | 内容 | 備考 |
|--------|------|------|
| Sign in with Apple 対応 | Clerk 経由で実装 | App Review 必須条件。Clerk は対応済み |
| iOS ログイン導線設計 | Free はログインなし、Basic 機能タップ時にサインイン促す | 起動時のログイン強制は絶対にしない |
| Web サブスク契約フロー | Stripe 決済。Web で完結 | App Store 課金は使わない。iOS アプリ内からの導線は地域別に要調査（Anti-steering 規制） |
| プラン状態 API | iOS がユーザーのサブスク状態を問い合わせて UI を出し分け | 既存の subscription API を拡張 |
| iPad 対応維持 | 現状の対応を崩さない | 前回の指摘事項 |

## Phase 1: Basic コア — Hoo が喋る

**目的**: Hoo 汎用会話の実現。Basic 課金開始

### タスク

| タスク | 内容 | 依存 |
|--------|------|------|
| iOS Clerk ログイン復活 | Free 時は不要、Basic 機能タップ時にサインイン | Phase 0 完了 |
| Hoo 汎用会話（iOS） | Haiku、無制限。既存 `/api/hoo/chat` を iOS から叩く | ログイン |
| Hoo 振り返りモード | 休憩タイマー発動 / セッション終了後に会話開始。作業中は喋らない | Hoo 会話 |
| クラウド同期 | ローカルデータを DB へ同期 | ログイン |
| Basic サブスク開始 | Web で Stripe 契約 → iOS で反映 | Phase 0 + ログイン |

### App Review 提出

Phase 1 の最小セット（Hoo 会話のみ追加）で審査に出す。
通過を確認してから Phase 2 の機能を順次追加する。

## Phase 2: Basic 完成 — ログが貯まる

**目的**: データ蓄積基盤の構築と見える化。Basic の完成形

### データフロー

```
[macOS] DAW Hub アプリ (Swift)
  │  OSC で DAW 操作ログを取得
  │  → API → DB (タイムスタンプ付き)
  │
  │                              ┌─ タイムスタンプで同期 ─┐
  │                              │                       │
  ▼                              ▼                       ▼
DB: DAW操作ログ ←──── 時間軸で結合 ────→ 音声文字起こしログ
  (EQ変更, トラック追加,                    (「低域もうちょい削ろう」
   ミュート切替, etc.)                       「このキックいい感じ」etc.)
                                              ▲
                                              │ Whisper (バッチ)
                                              │
                                    [iOS] MUEDnote アプリ
                                      ├─ 休憩タイマー
                                      └─ ボイスレコーダー
```

### タスク

| タスク | 内容 | 依存 |
|--------|------|------|
| Whisper バッチ文字起こし | 録音終了後に OpenAI Whisper API で処理 | Phase 1（クラウド同期） |
| DAW ログ API | macOS Hub → OSC → API → DB | Phase 1（認証基盤） |
| タイムスタンプ同期 | 音声文字起こしログ × DAW 操作ログをタイムスタンプで結合 | Whisper + DAW ログ |
| 見える化 UI | 練習時間、作業傾向の可視化（「今週 EQ 作業が 40%」等） | 同期完了後 |

### 見える化の段階

| データ活用 | Basic（Phase 2） | Premium（Phase 3） |
|-----------|-----------------|-------------------|
| 練習時間の可視化 | 今週何時間、何曜日に集中 | 同左 |
| DAW ログ閲覧 | 記録一覧、タグ付け | 同左 |
| 簡易サマリー | 「今週は EQ 作業が多かった」程度 | 深い分析 + 傾向検出 |
| Hoo の反応 | 汎用（「今日もお疲れ」程度） | あなたの傾向を踏まえた具体的助言 |

## Phase 3: Premium — Hoo が覚醒する

**目的**: 蓄積データによる Hoo 個人化。Premium 課金開始

### 前提

Phase 2 でデータが十分蓄積されていること。蓄積量と個人化品質の関係は Phase 2 運用中に検証する。

### タスク

| タスク | 内容 | 依存 |
|--------|------|------|
| MUEDlobe 統合 | Premium でアンロック。認知プロファイル測定 | Phase 1（認証基盤） |
| Hoo 個人化プロンプト | 蓄積データ + 認知プロファイルをシステムプロンプトに注入 | Phase 2 + MUEDlobe |
| Premium サブスクプラン追加 | Stripe に上位プラン追加 | Phase 0（Stripe 基盤） |

### Premium の Hoo が持つコンテキスト

```
【このユーザーについて】
- パターン認識が強い（MUEDlobe: pattern-complete 上位12%）
- 聴覚記憶は平均的（tone-sequence 中央値付近）
- 集中持続は短め（focus-flow: 平均セッション4分）
- DAWログ傾向: EQ作業に時間をかけすぎる
- 最近の練習: 3日連続でミックスダウン中心
- 音声メモ: 「低域が気になる」発言が多い
```

同じ Haiku でも、このコンテキストがあるかないかで応答品質が根本的に変わる。
