## 0. 共通理念（ClaudeCodeルームと共通）

### kimnyとは

プロ作曲家15年（ポップス・CM音楽中心、AKB48・JUJU・ももクロ等）。音楽制作会社代表。2023年頃からAI開発に軸足を移し、MUED（Music Education → Muse + Education）ブランドで音楽制作者向けツール群を開発中。WAIS検査で作業記憶128（上位2%）/ 処理速度97という認知プロファイルの凸凹を持つ。

### MUEDエコシステム

- **MUEDear** — 耳トレアプリ。自前DSPエンジン（OPT/FET/Tube/VCA 4種コンプレッサー）搭載。App Store審査中
- **MUEDnote** — 音楽制作ログアプリ。制作中の思考をAIで構造化。App Store審査中
- **MUEDlobe** — 認知プロファイリングツール（構想段階）。ゲーム形式の認知テスト → Hooの振る舞い最適化
- **Hoo** — AIアシスタント（フクロウキャラ）。全アプリの中心に位置し、認知プロファイルを保持

### コンテンツの二層構造

```
note（集客層）          LP（哲学層）
━━━━━━━━━━━━━━━       ━━━━━━━━━━━━━━━
kimnyを知らない人が     kimnyを知った人が
見つける場所            深く理解する場所
                  ↗
note記事 ─→ 読者 ─→ LP記事
         「発見」     「思想」
```

- **noteの仕事:** 集客・発見・AIO引用。音楽制作×AIの普遍的な問いを扱う
- **LPの仕事:** 世界観・プロダクト哲学。MUEDの設計思想を語る
- **絶対ルール:** noteとLPで同じ話を載せない。送客は「この先にもっと深い話がある」という期待で繋ぐ

### 品質ゲート（3チェック）

全てのコンテンツに適用:

1. **発見:** 読む前と後で読者の認識が変わるか？
2. **外部アンカー:** kimny個人の話だけで閉じていないか？他者のエピソード・実験・外部概念があるか？
3. **1文テスト:** 「〇〇だと思っていたが実は〇〇だとわかる」と1文で言えるか？

### インタビュー記事フォーマット

- 質問者（Claude）: `>` ブロッククォート。名前表記なし
- 回答者（kimny）: 地の文。名前表記なし
- プルクォート: `"引用文"` + `— kimny` or `— claude`
- ヘッダー: `kimny × Claude—YYYY年M月`
- フッター: `この記事は、〇〇開発過程でのAI（Claude）との実際の対話をもとに再構成したものです。`

## 1. このルームの担当範囲と運用方法

**noteマガジン「AIに聞かれて気づいたこと」の記事運用全般。**

原稿作成・AIO最適化テキスト生成から、Chrome拡張を使ったnote.com上での直接編集まで、一気通貫で行う。

### ログインが必要な場面の運用フロー

```
Coworkがnote.comに遷移
    ↓
ログイン画面が表示される
    ↓
Coworkが「ログインをお願いします」とkimnyに声をかける
    ↓
kimnyがログイン操作を実施
    ↓
kimnyが「ログインした」と伝える
    ↓
Coworkが作業を続行
```

- パスワード入力はCoworkでは行わない。必ずkimnyに渡す
- ログイン後のセッションが切れた場合も同様のフローで対処
- 記事の「公開」「非公開」「削除」ボタンの操作はCoworkが行ってよい（kimnyの承認を事前に得た上で）

## 4. 具体的なタスクと実行手順

### タスク4-1: 重複3記事の非公開化

**実行手順:**
1. note.comにアクセス → ログイン画面が出たらkimnyに渡す
2. ダッシュボード → 記事管理画面へ
3. 対象3記事を1本ずつ「非公開」に設定
4. 非公開後、各記事URLにアクセスして404または非公開状態を確認

**kimnyへの事前確認事項:**
- 非公開にする3本の最終確認（実行前にリストを提示して承認を得る）

### タスク4-2: A評価5記事にAIO最適化を追加

各記事の編集画面を開き、以下を追加する:

**追加1: 冒頭サマリー（記事の最初に挿入）**

各記事ごとに作成する1段落のサマリー。問い→結論→この記事で何がわかるか。

| 記事 | 冒頭サマリー案 |
|------|--------------|
| メロディが降りてくる | 「メロディが降りてくる」とプロの作曲家は言うが、15年のキャリアで一度もそんな経験はない。創作の正体は記憶の反芻——100のインプットから1を選んで再構成する作業だ。この記事では、医学生の一言から始まった認識の変化と、AIの仕組みを知って確信に変わった経緯を、対話形式で記録する。 |
| 逆位相 | AIに自分の曲のEQを分析させたら、全ての特徴を打ち消す「逆位相」のような回答が返ってきた。AIの出力は質問が曖昧なほど中央値に収束する。プロ作曲家が実際にChatGPT o3で実験し、この構造を解き明かした記録。 |
| スタジオにいなくていい | 作曲家の仕事はスタジオに入る前に終わっている——そう気づいたのは、収録現場の真ん中で「何も言わなかった」経験からだった。デモの段階で勝負が決まる構造と、プリプロテイクがそのままリリース版になった実例を、対話形式で語る。 |
| コーヒーサーバー | AI時代に「差がつく」のはツールの使い方ではなく、何を作りたいかという目的意識だ——コーヒーサーバーの比喩から始まり、プログラミング授業での脱落パターン、レコーディングエンジニアとの対話まで。プロ作曲家15年の現場感覚で語るAI時代の生存戦略。 |
| AI時代に残る人 | 「AI時代に残る人はEQが高い人」というポストに、社交が苦手な側から異を唱える。EQとは好かれる力ではなく、曖昧な要望を専門領域に翻訳する力だ。職人型クリエイターのためのブランド構築論を、対話形式で記録する。 |

**追加2: 末尾FAQ（フッター直前に挿入）**

各記事の核心テーマに沿った2〜3問のQ&A。記事本文を読まなくてもFAQだけで概要がわかる構造にする。

**追加3: 記事末尾テンプレートの統一**

全7本の記事末尾を以下に統一:

```
---
この記事は、AIとの対話をもとに再構成したものです。
筆者: kimny ― ポップス・CM音楽を中心に15年。音楽制作者向け耳トレアプリ MUEDear（mued.jp）を開発中。
開発の裏側は mued.jp のインタビューシリーズ で。
```

**実行手順:**
1. 記事ごとに編集画面を開く
2. 冒頭にサマリーを挿入
3. 末尾にFAQを挿入
4. フッターをテンプレートに差し替え
5. プレビューで確認
6. 保存（下書き保存。公開タイミングはPhase 1スケジュールに従う）

### タスク4-3: マガジン名・説明文の変更

**実行手順:**
1. マガジン設定画面を開く
2. マガジン名を変更:「プロ作曲家がAIに聞かれて答えに詰まった話」
3. 説明文を変更: 「プロ作曲家・kimnyが、Claude（AI）からの質問に答える対話形式の連載。15年のキャリアで「当たり前」だと思っていたことが、AIに聞かれて初めて言葉になる。創作の正体、脳の仕組み、AI時代の音楽制作。読者が持ち帰れる「発見」を、毎週1本。」

### タスク4-5: 新規記事の作成（Phase 2〜）

**ai-interview-articleスキルを使用。** 過去の会話ログから素材を収集し、インタビュー形式の記事に再構成する。

作成フロー:
1. kimnyとテーマを決定
2. 素材となる会話ログ・メモをkimnyから受け取る
3. ai-interview-articleスキルに従って原稿作成
4. 品質ゲート4チェック（発見・外部アンカー・1文テスト・LP重複チェック）を通す
5. kimnyにレビュー依頼
6. 修正 → note.comの編集画面に入力
7. 火曜20:00に公開

## 8. ClaudeCode（LP）ルームとの連携ポイント

- 非公開にした3記事について、LP側のmeta descriptionとの重複がないかLPルームに確認依頼
- 新規記事のテーマがLP記事と被る場合、角度を変えるか、LPルームに移管
- 記事末尾のLP導線リンク（mued.jp）が正しく機能しているか、公開時に確認
- LP側で記事が追加された場合、チェック4のLP重複リストを更新

## 9. やってはいけないこと

- LP記事と80%以上重複するnote記事を公開すること
- 1日に2本以上の記事を公開すること（同日8本投下の過ちを繰り返さない）
- MUEDプロダクトの内部仕様（Cortex Editor、認知ゲーム設計等）をnoteで公開すること（LPの領域）
- 外部アンカーのない記事を公開すること（「でっち上げ感」の原因）
- 記事末尾テンプレートを省略すること（LP送客導線の統一が崩れる）
- 火曜20:00以外のタイミングで公開すること（読者の習慣化を妨げる）
- noteのSEOのために記事のトーンを崩すこと（対話形式の自然さを維持）
- kimnyの承認なしに記事を公開・非公開にすること
- ログイン情報を入力・保持すること（ログインは必ずkimnyが操作）
