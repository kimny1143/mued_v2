# MUEDnote ユーザーシナリオ — 制作フローのどこに居るか

**作成日**: 2026-02-27
**目的**: MUEDnote が音楽制作のワークフローにどう入り込むかを具体的に描く

---

## 今できること（v1.0.1 + Hub）

パイプラインは一通り繋がっている:

| 機能 | 状態 |
|------|------|
| タイマー（4モード） | 動作 |
| セッション中の音声録音 | 動作 |
| Whisper 文字起こし | 動作 |
| Hoo AI チャット（Haiku） | 動作 |
| Hub → DAW ログ → API → DB | 動作 |
| DAW ログ × 音声のタイムスタンプ同期 | 動作 |
| DAW ログ → Hoo の会話コンテキストに反映 | 動作 |
| 見える化 UI（制作パターンの可視化） | 未着手 |

### Hub が送っている DAW ログの中身

```json
{
  "action": "parameter_change",
  "value": 0.6234,
  "value_string": "2.40 kHz",
  "metadata": {
    "track_name": "Kick",
    "device_name": "Pro-Q 3",
    "param_name": "Band 1 Frequency"
  }
}
```

- トラック名、プラグイン名、パラメータ名、人間が読める値 — データの粒度は良い
- FabFilter Pro-Q は専用フォーマッタで Hz/dB/Q を正確に変換している
- 200ms ポーリング + 500ms デバウンスでノブのスクラブノイズも除去済み

### Hoo に渡される形式（現状）

```markdown
### 直近の操作詳細（新しい順）
- 17:05 / パラメータ変更 / Track: Kick / Device: Pro-Q 3 → 2.40 kHz
- 17:04 / トラックボリューム / Track: Bass → -3.5 dB
- 17:02 / パラメータ変更 / Track: Kick / Device: Pro-Q 3 → -4.5 dB
- 17:00 / パラメータ変更 / Track: Kick / Device: Compressor → 3.2
```

日別サマリー（操作件数・アクション内訳・使用トラック/プラグイン一覧）+ 直近10件の詳細。

### 現状の問題: ログは貯まるが、意味が伝わらない

Hoo はこのログを見て「パラメータが変わったんだね」以上のことが言えていない。
データは揃っているのに、**音楽的な解釈**が欠けている。

## ログ解釈の3段階

### Level 0: 今の状態（データの羅列）

```
- Pro-Q 3 Band 1 Frequency → 2.40 kHz
- Pro-Q 3 Band 1 Gain → -4.5 dB
- Compressor Threshold → -18 dB
- Pro-Q 3 Band 1 Frequency → 2.20 kHz（再調整）
```

Hoo「Pro-Q 3 のパラメータを何度か変更していますね」← 何も分かってない

### Level 1: パラメータの音楽的翻訳

```
- Kick の 2.4kHz を -4.5dB カット（中域のボクシーさを削った）
- Kick にコンプレッサーを適用（Threshold -18dB）
- Kick の EQ を 2.2kHz に微調整
```

Hoo「Kick の中域をカットしてからコンプをかけたんだね。
　　コンプの後に EQ を微調整してるから、コンプで帯域バランスが変わったのかも」

### Level 2: 行動パターンの解釈

```
セッション分析:
- 50分中、Kick トラックに 35分費やした
- EQ → コンプ → EQ の手戻りパターンが発生
- Bass トラックは最後の5分でボリューム調整のみ
```

Hoo「Kick に全体の70%の時間を使ったね。
　　EQ→コンプ→EQ の往復が起きてるから、
　　次回はコンプを先にかけてからEQで仕上げる順番を試してみない？」

### Level 3: 長期トレンド（Phase 3 / Premium 相当）

```
過去2週間の傾向:
- ミックス開始時に必ずキックから着手する
- 低域 EQ の調整に平均セッション時間の 40% を消費
- 後半のセッションほどマスターバスの操作が増える（疲労？）
```

Hoo「いつもキックから始めるけど、たまにベースから攻めてみない？
　　低域の基準をベースで作ってからキックを合わせると、
　　EQ の手戻りが減るかもしれない」

## シナリオ A: ミックス作業（現状 — Level 0）

**ケイ**: フリーランスのミックスエンジニア
**環境**: MacBook Pro + Ableton + Hub、iPhone はデスク横

```
14:00  Ableton を開く。Hub が自動でログ取得開始
       iPhone で MUEDnote、Standard (50分) で開始

14:00-14:50  ミックス作業
       Kick の EQ を何度か調整（Pro-Q 3）
       コンプをかけてからまた EQ を触り直す
       ときどき「うーん、ローがまだ重いな...」と独り言
       → Hub は全操作をログ。MUEDnote は音声を録音中

14:50  タイマー終了。休憩画面
       → 文字起こし:「ローがまだ重いな」
       → Hoo のコンテキストに DAW ログ（操作件数・直近10件）が入る

       ケイ「今日のミックスどうだった？」
       Hoo「今日は84件の操作がありました。
            Kick トラックの Pro-Q 3 を中心に作業していたようですね。
            何か行き詰まったポイントはありましたか？」

       ← Level 0: 件数とトラック名は言えるが、中身が薄い
       ← ケイは「それは自分で分かってる」と感じる
```

### このシナリオの正直な評価

- Hub + DAW ログの仕組みは動いている
- でも Hoo の返答が「操作件数のレポート」にしかなっていない
- ユーザーが自分で分かっていることを繰り返されても価値がない
- **「ChatGPT に直接聞いた方が早い」と比較される**

## シナリオ B: 同じミックス作業（Level 1 到達後）

```
14:50  タイマー終了。休憩画面

       → ログ解釈エンジンが動く:
         ・Kick の Pro-Q 3: 2.4kHz を -4.5dB カット → 中域のボクシーさ除去
         ・Kick にコンプ追加 (Threshold -18dB, Ratio 4:1)
         ・コンプ後に EQ 再調整 (2.4→2.2kHz) → コンプ起因の手戻り
         ・Bass のボリュームを -3.5dB 下げた
         ・音声メモ (14:08):「ローがまだ重いな」

       ケイ「今日のミックスどうだった？」
       Hoo「Kick の中域を削ってコンプかけたね。
            コンプ後にまた EQ を触り直してるから、
            コンプで帯域バランスが変わったっぽい。
            ローが重いって言ってたけど、
            Bass も -3.5dB 下げてるし、低域全体のバランスで悩んでた？」

       ← これなら「分かってるな」と感じる
       ← Hoo が DAW ログと音声メモを交差させて文脈を掴んでいる
```

### Level 0 → 1 の差

| | Level 0（今） | Level 1（目標） |
|--|--------------|----------------|
| Hoo の発言 | 「84件の操作がありました」 | 「Kick の中域を削ってコンプかけたね」 |
| ユーザーの感想 | 「それ自分で分かってる」 | 「お、ちゃんと見てるな」 |
| 会話の深さ | 自分から説明しないと進まない | Hoo から具体的な話題を振れる |
| ChatGPT との差別化 | ほぼなし | DAW の操作履歴という固有の文脈 |

## シナリオ C: 作曲・アレンジ作業

**ユキ**: シンガーソングライター
**環境**: MacBook + Logic Pro（Hub 未対応）、iPhone

```
20:00  新曲のアレンジ開始。Deep Work (90分)
       → 「今日はBメロのコード進行を決める」

20:00-21:30  作業中の独り言
       → 「サブドミマイナーにしたら暗すぎるか」
       → 「これいいかも。ストリングス入れたら化けそう」
       → 「あ、Cメロへの繋ぎが思いつかない...」

21:30  タイマー終了
       → 文字起こし: 上記3つの断片

       ユキ「Bメロは決まったけどCメロへの繋ぎで詰まった」
       Hoo「IVm を使ったんだね。Cメロに行くなら、
            IVm → bVII → I みたいに半音下降で繋ぐのも一つの手だよ」
```

### このシナリオの特徴

- DAW ログなし（Logic 未対応）→ 文字起こし + 直接会話が全て
- 作曲中は独り言が多い → 文字起こしの価値が相対的に高い
- Hoo の音楽理論知識は Haiku でもそれなりに出る
- **ただし「ChatGPT に聞いても同じ」問題はここでも発生する**

### DAW ログがない環境での差別化

- タイマーで「区切り」を作る効果（ダラダラ防止）
- 録音 → 文字起こしで「今日やったこと」が自動で残る
- Hoo が過去の会話を覚えている（累積の文脈）
- これらは ChatGPT にはない。が、¥1,980/月 の価値として十分か？

## 核心の問い

### 1. 今すぐ解決すべきこと: ログ解釈

Level 0 → Level 1 に上げないと、DAW ログ連携の価値が伝わらない。

**技術的に必要なこと**:
- `buildDawLogContext()` でログを Hoo に渡す前に、パラメータの音楽的意味を付与する
- 例: `Pro-Q 3 Band 1 Gain → -4.5 dB` → `Kick の 2.4kHz 帯域を -4.5dB カット`
- 既にトラック名・プラグイン名・パラメータ名・値がある → 変換ルールを書けばいい
- EQ のカット/ブースト、コンプの設定、ボリューム変更 etc. を音楽用語に翻訳

### 2. 中期の問い: Hub 対応 DAW の拡張

- 現在 Ableton のみ。Logic Pro / Pro Tools は？
- Logic ユーザー = 作曲家に多い = 独り言多い = 文字起こしで価値を出せる層
- でも Hub がなくても文字起こし + Hoo チャットで最低限の体験はある

### 3. 本質的な問い: MUEDnote は何のアプリか？

- **タイマーアプリ？** — iPhone 標準で十分。差別化できない
- **音声メモアプリ？** — Otter.ai、Whisper 単体でいい。差別化できない
- **AI チャットアプリ？** — ChatGPT でいい。差別化できない
- **制作ログ × AI 分析アプリ？** — これは他にない。が、Level 1 以上の解釈が必要

**MUEDnote の固有価値 = 「DAW の操作ログと音声メモを時間軸で統合し、AI が音楽的に解釈する」**

この価値が体験として伝わるかどうかは、ログ解釈の品質に直結する。
