# 内蔵Hoo POC指示書

## 概要

MUEDnote内に「Hooと会話」機能を実装する。
ライトユーザー向けの有料オプションとして提供。
プロンプト設定不要で、開いたらすぐHooと会話できる状態を作る。

---

## POCのスコープ

### やること
- Hooとのチャット画面の実装
- LLM API連携（Claude API）
- Hooプロンプト（レベル1+2）の組み込み
- 会話のログ化（フォーマットに沿った出力）
- ログをMUEDnoteに保存する導線

### やらないこと（後回し）
- 課金・プラン制御
- ユーザー認証との連携
- 会話履歴の永続化
- 複数会話の管理

---

## 技術要件

### フロントエンド
- チャットUI（入力欄 + 会話表示エリア）
- 「ログ化する」ボタン
- ログ出力のプレビュー/編集画面

### バックエンド
- Claude API
- システムプロンプトにHooプロンプト（レベル1+2）を設定
- ストリーミングレスポンス対応

### ログ連携
- 会話終了時、フォーマットに沿ったログを生成
- MUEDnoteのログ保存機能に渡す

---

## モデル選定

### POC段階
- **Claude Opus 4.5**で検証
- まず品質を確認し「Hooらしさ」が出るか見る

### 本番
- 検証結果次第で決定
- Sonnet 4で十分なら切り替え（コスト削減）
- Opusじゃないとダメなら価格設定で吸収

---

## 評価指標

### 1. キャラクター維持
- 「ほほう」が適切なタイミングで出るか（乱用してないか）
- 口調がユーザーに同調していくか
- 余計な褒めや装飾をしてないか

### 2. 思考引き出し
- 問い返しが的確か
- ユーザーの発言を構造化できてるか
- 一般論で逃げてないか

### 3. 論点整理
- 構造化が明確か（箇条書き、分類など）
- 「変わる/変わらない」等の切り分けができてるか
- 結論を急がず相手に言語化させてるか

### 4. ログ出力
- トリガーワードを正しく認識するか
- フォーマット通りに出力されるか
- 会話内容が適切に要約されてるか

### 5. コスト効率
- 1会話あたりのトークン消費
- レスポンス速度

---

## 検証方法

1. 同じ会話シナリオをOpus 4.5 / Sonnet 4で実行
2. 上記指標で5段階評価
3. 3会話分くらい試してスコア比較

---

## Hooプロンプトの組み込み

```
システムプロンプト = レベル1 + レベル2の全文
```

- ユーザーの最初のメッセージから会話開始
- 「まとめて」「ログにしたい」等のトリガーワードでログフォーマット出力

---

## 画面フロー

```
1. 「Hooと会話」を開く
2. チャット画面表示
3. ユーザーが入力 → Hooが応答（繰り返し）
4. ユーザーが「まとめて」等と入力
5. Hooがログフォーマットで出力
6. 「このログを保存」ボタン表示
7. 保存 → MUEDnoteのログ一覧に追加
```
