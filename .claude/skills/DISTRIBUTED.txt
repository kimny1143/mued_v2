# Skills distributed here by claude-code-template, whose canonical copy lives in THAT repo.
#
# ★Why this file exists. `.gitignore` excludes `.claude/skills/*` with a small allowlist, so a
# skill that is neither a symlink nor on the allowlist is invisible to git — `git status` says the
# repo is clean while the file exists on exactly one disk. On 2026-08-29 three mued-authored skills
# were in that state (web-performance, mued-onboarding, legal-compliance — 43 KB, two of them named
# in CLAUDE.md). The .gitignore now protects those, and this file closes the other half: it turns
# "everything else, ignored" — an unnamed, uncountable set — into an explicit list.
#
# ★The rule scripts/verify/skill-durability.ts enforces: every real (non-symlink) directory under
# .claude/skills must be EITHER tracked by git (this repo is canonical) OR listed below (the
# template repo is canonical). Anything in neither has no recovery path, and the check fails.
#
# ★A new distribution will therefore turn the check red until its skill is added here. That is the
# intended behaviour: a newly arrived skill should be CLASSIFIED, not silently ignored. Adding a
# line is the whole fix.
#
# ★Do not list symlinks — git does not follow them, and they are covered by the template repo.
# ★CORRECTION (re-measured 2026-08-30, git 2.48.1). This note used to say check-ignore "reports
# not ignored" through a symlinked path. It does not: it REFUSES.
#     git check-ignore -v .claude/skills/tdd/SKILL.md   → rc=128  fatal: pathspec ... is beyond a symbolic link
#     git check-ignore -v .claude/skills/tdd            → rc=0    .gitignore:78:.claude/skills/*
# ★So the symlink itself IS matched (rc=0); only a path THROUGH it is rejected, and with --stdin the
# refusal takes the rest of the batch with it. The old wording would have had someone read a silent
# rc=1 that never occurs — a wrong shape for the failure, in a note whose whole job is the failure.
#
# One skill name per line. Blank lines and #-comments are ignored.
