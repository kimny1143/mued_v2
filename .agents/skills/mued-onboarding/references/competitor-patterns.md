# Competitor & Reference App Onboarding Patterns

MUEDアプリ群のオンボーディング設計に参考となるアプリのパターン分析。
直接競合（音楽教育）と間接参考（学習アプリ全般）の両方を収録。

---

## 直接競合: 音楽教育・耳トレアプリ

### ToneGym（Web）
- **カテゴリ**: 音楽家向け耳トレ（Web）
- **オンボーディング方式**: Learn by Doing
- **Aha Moment**: 最初のゲームクリア → スコア表示 → リーダーボードでの位置確認
- **良い点**: ゲーム化が徹底、多様なゲームで飽きない、ランキングによる競争心理
- **課題**: Web専用で移動中の学習に向かない
- **MUEDへの示唆**: ゲーム化の粒度とバリエーションを参考に

### SoundGym（Web）
- **カテゴリ**: オーディオエンジニア向け耳トレ（Web）
- **オンボーディング方式**: Function-Oriented + ゲーミフィケーション
- **Aha Moment**: EQゲームで周波数を当てられた瞬間
- **良い点**: プロ向けに特化、実務直結のスキル訓練
- **課題**: 初心者には敷居が高い
- **MUEDearとの差別化**: MUEDearはコンプ/EQ/リバーブをカスタムDSPで再現 → 「実機の音」

### EarMaster（マルチプラットフォーム）
- **カテゴリ**: 総合耳トレ
- **オンボーディング方式**: Progressive Disclosure
- **Aha Moment**: AI適応でレベルが自動調整される瞬間
- **良い点**: 教育機関採用多数、体系的カリキュラム
- **課題**: UIが古め、ゲーム性が低い
- **MUEDへの示唆**: カリキュラムの体系性は参考に、UIモダン化で差別化

### Functional Ear Trainer（iOS）
- **カテゴリ**: 相対音感トレーニング特化
- **オンボーディング方式**: 即体験型（説明最小限 → すぐ始める）
- **Aha Moment**: スケール度数を「感覚で」わかるようになった瞬間
- **良い点**: スコープが狭く深い、無料、UIシンプル
- **課題**: コード聴音非対応、カスタマイズ限定的
- **MUEDへの示唆**: 「1つのことを深くやる」姿勢の説得力。MUEDearのコンプ聴き比べも同じ哲学

### Complete Ear Trainer（マルチプラットフォーム）
- **カテゴリ**: 総合耳トレ（段階的解放型）
- **オンボーディング方式**: Progressive Disclosure（チャプター制）
- **Aha Moment**: 3つ星獲得で次チャプター解放
- **良い点**: 段階的難易度、カスタムドリル作成可、教師向け機能
- **課題**: 買い切りモデルで継続利用のインセンティブが弱い
- **MUEDへの示唆**: チャプター解放の達成感設計、カスタムプログラム機能

## 間接参考: 学習・習慣化アプリ

### Duolingo（語学学習）— 最重要参考
- **オンボーディング方式**: Gradual Engagement + Learn by Doing + Personalization
- **フロー概要**:
  1. 言語選択（「I want to learn...」一人称）
  2. 目的選択（旅行/学校/脳トレ等）
  3. デイリー目標設定（5分/10分/15分/20分）
  4. レベル判定 or 基礎レッスン開始（← ここが最初の体験）
  5. レッスン完了 → XP獲得 → ストリーク開始
  6. アカウント作成（レッスン完了後）
- **Aha Moment**: 初回レッスン完了時にXPとストリークを獲得
- **数値**: 7日ストリーク維持 → Day30リテンション90%
- **核心的学び**:
  - 登録を「体験の後」に配置
  - フローが長くても、ユーザーが「自分のために使っている」と感じれば離脱しない
  - 互恵性: 先に価値を与える → 登録への心理的義務感
  - Free Reversed Trial: プレミアム体験14日 → 習慣形成後に課金判断

### Headspace（瞑想）
- **オンボーディング方式**: Personalization-first
- **フロー概要**: 目的選択 → スキルレベル → 3分の体験瞑想 → 登録
- **Aha Moment**: 初回瞑想後の「少し落ち着いた」感覚
- **MUEDnoteへの示唆**: ブレイク管理も同じ「体験後に価値を感じる」パターン

### Spotify（音楽ストリーミング）
- **オンボーディング方式**: Personalization-first → Algorithmic Curation
- **フロー概要**: 3アーティスト選択 → 通知設定 → パーソナライズされたホーム
- **Aha Moment**: 自分の好みに合ったプレイリストが即座に生成される
- **MUEDearへの示唆**: 音楽ジャンル/使用機材の選択で体験をカスタマイズ

### Canva（デザイン）
- **オンボーディング方式**: Learn by Doing + Checklist
- **フロー概要**: テンプレート選択 → ガイド付き編集 → 作品完成
- **Aha Moment**: 最初のデザインが完成した瞬間
- **視覚的チェックリスト**: 各ステップの完了で進捗%表示 + 「You did it!」メッセージ
- **AI Mixingサービスへの示唆**: ファイルアップロード → プレビュー再生の「作品完成」体験

### Notion（ドキュメント/ナレッジ管理）
- **オンボーディング方式**: Progressive Disclosure + Template
- **Aha Moment**: テンプレートを使って最初のページを作った瞬間
- **MUEDnoteへの示唆**: メモのテンプレート/サンプルデータの提供

### LinkedIn（プロフェッショナルSNS）
- **オンボーディング方式**: Progressive（4段階プロフィール構築）
- **核心**: 関係構築を自然に促す → フォロー → コネクション → アプリ使用
- **MUEDlobeへの示唆**: 認知プロファイルの段階的構築

### Wise（国際送金）
- **オンボーディング方式**: Value Before Registration
- **核心**: ログイン前にレート確認可能 → 価値の即時証明
- **AI Mixingサービスへの示唆**: 登録前にサンプル音源のマスタリング結果を試聴

## パターン分類と適用ガイド

各MUEDアプリに推奨するオンボーディングパターンの組み合わせ:

### MUEDear
**Primary**: Learn by Doing（Duolingo型）
**Secondary**: Personalization-first（レベル分岐）
**理由**: 耳トレは「やってみないとわからない」領域。即体験が最重要。
レベル差が大きいためパーソナライズ必須。

### MUEDnote
**Primary**: Value Before Registration（Wise型）
**Secondary**: Progressive Disclosure（LinkedIn型）
**理由**: メモ1件 + ブレイク1回を登録前に体験させる。
機能は段階的に開放（ブレイク → メモ → 音声 → 統計）。

### MUEDlobe
**Primary**: Learn by Doing + Personalization
**Secondary**: Progressive Disclosure（全7ゲームへの段階的誘導）
**理由**: 認知テスト自体がコンテンツ。1ゲーム完了 → 結果表示がAha。

### AI Mixing/Mastering
**Primary**: Value Before Registration（Wise型 → 即結果プレビュー）
**Secondary**: Learn by Doing（Canva型 → ガイド付きアップロード）
**理由**: 「自分の音源が変わる」体験が最強のAha。登録前にサンプルプレビューを提供。

## 反面教師パターン（避けるべき設計）

1. **情報過多ウェルカムスライド**: 3枚以上の説明スライドはスキップ率が急上昇
2. **価値体験前の登録強制**: Busuu方式（登録→通知→価値）は動機付け失敗
3. **過剰なパーミッション要求**: 起動直後にカメラ・位置情報・通知を一括要求
4. **見せかけのパーソナライズ**: 質問だけして体験が変わらない → 信頼喪失
5. **長すぎるチュートリアル**: ツールチップ5個以上の連打 → 80%がスキップ
6. **空のホーム画面**: 登録完了後に何もない画面 → 次のアクションがわからず離脱
7. **短期的圧力戦術**: 「今だけ50%OFF」等のオンボーディング中のプレッシャー → 信頼毀損
